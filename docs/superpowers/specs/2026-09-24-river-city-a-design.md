# A안 — 한강형 혼합 도시 설계

날짜: 2026-09-24
상태: A안 방향 승인 완료. 상세 설계 검토용.

## 의도와 기준 시안

사용자는 오픈월드의 도로망을 다채롭게 만들고, 서울 한강을 연상시키는 강변 공원과 인공섬을 원한다. 비주얼 컴패니언에서 비교한 세 방향 중 A안(한강형 혼합 도시)을 선택했다.

목표는 강을 건너면 도로와 풍경의 성격이 바뀌고, 운전하다 공원 입구에서 내려 물가와 섬까지 걸어갈 수 있는 미니어처 도시다. 실제 서울 지도를 복제하지 않는다.

승인한 시안 원본: `.superpowers/brainstorm/537395-1790229194/content/river-city-concepts.html`의 A안. 기존 도로 비교는 extent 1844의 생성 결과이며, 제안 지도와 입체도는 배치 개념도다. 시안의 픽셀 좌표·교량 수·건물 위치를 실제 도시 좌표로 그대로 변환하지 않는다.

## 공간 구성

| 공간 | 경험 | 생성 규칙 |
| --- | --- | --- |
| 북안 구도심 | 코너마다 시야가 바뀌는 작은 블록과 상가 골목 | 강 북쪽의 생활도로를 완만한 곡선과 엇갈린 T자로 구성하고, 연결부 밖에 포켓 광장을 둔다 |
| 남안 도심 | 긴 직선 시야와 대각선으로 가로지르는 선택 경로 | 기존 격자와 간선을 연결하는 대각 대로 한 축을 만들고, 자투리 삼각 부지를 광장·녹지로 예약한다 |
| 양안 경관도로 | 강의 굽이를 따라 달리는 연속 경로 | 기존 공원 바깥 강변도로를 사용하고, 공원 입구에서만 진출입·정차 공간을 연결한다 |
| 남안 잔디공원 | 넓은 잔디와 그늘, 물을 향한 열린 시야 | 기존 넓은 공원 띠 안에서 잔디마당·그늘숲·수변 계단·연속 산책로를 배치한다 |
| 동쪽 문화섬 | 낮은 공연시설과 잔디 객석 | 기존 `nodeul` 섬을 이용하고 양안 산책로로 이어지는 보행 연결을 둔다 |
| 남안 수상 정원 | 서로 다른 크기의 세 파빌리온 | 문화섬 동쪽 남안 가까이에 정적인 수상 데크와 짧은 보행 연결을 만든다 |

서쪽 `yeoui` 섬은 낮은 녹지와 산책 공간으로 정돈해 문화섬과 실루엣을 구분한다. B안의 추가 외곽 주행 루프와 C안의 추가 정원섬은 범위에 포함하지 않는다.

## 도로와 필지

기존 공항 접근로·고가 순환망·차량 교량을 기준 연결망으로 삼는다. 북안 생활도로와 남안 대각축은 이 망에 실제로 접속해야 한다. 북안에서도 지구 간 간선은 읽기 쉬운 방향을 유지하고, 모든 길을 구불구불하게 만들지 않는다.

북안은 강 북쪽 도시화 부지에서 연속된 블록 묶음을 결정적으로 선택한다. 집산로를 잇는 곡선 생활도로와 짧은 연결 골목으로 작은 블록을 만든다. 곡선의 시작·끝 접선은 접속 도로 방향에 맞추고 차도 폭을 포함한 회전 여유를 확보한다. 새 주요 생활도로에는 서로 다른 두 진출입과 적어도 하나의 주행 순환을 둔다.

남안 대각축은 남서쪽 내부 간선에서 동쪽 남안 집산로까지 이어지는 하나의 연속 경로다. 실제 후보 노드와 지형 예약으로 시작·끝을 정하고, 강변 공원·지천·자연지대를 침범하지 않는 경로를 선택한다. 지천을 건너는 곳은 도로 방향과 수면 교차에서 교량을 파생한다. 곡선 또는 대각선 밑에 기존 필지를 남기지 않는다.

새 선형과 교차영역을 먼저 예약한 다음 블록·필지를 배치한다. 사각 블록을 사용할 수 있는 구역은 유지하고, 경계의 잘린 필지는 공통 점유 검사로 제외한다. 새 도로에 접한 배경 건물은 도로 방향을 따르는 전면 여백으로 구역 차이를 드러낸다. 제작자 전원 배치와 티어 혼합·높이 정책을 보존한다. 필지 변경에 따른 제작자 이동 수와 도시 extent 변화를 측정한다.

도로 폭·차선·속도는 현재 `roadProfile`과 `ROAD_WIDTH` 정책을 따른다. 시안의 굵은 선 때문에 차선 수를 별도로 바꾸지 않는다. `plan.roundabouts`는 현재 열린 교차면이므로 시안의 원형 표식을 중앙 섬으로 구현하지 않는다. 포켓 광장은 실제 차도·회전 공간 옆에 둔다.

## 강변 부지와 접근

위치의 기준은 `riverCenter`, `riverHalf`, `riverParkWidth`, `riverIslands`다. 강 중심선과 양안 폭의 차이를 활용한다. 후보 시설은 강변의 정규화된 위치를 기준으로 탐색하되 교량·램프·지천·기존 습지와 겹치는 구간을 피한다. ID와 고정된 후보 순서로 동률을 해소한다.

남안 잔디마당은 서쪽 섬을 바라보는 넓은 공원 구간에 둔다. 기존 습지와 연못은 피하거나 잔디마당의 가장자리 풍경으로 연결한다. 산책로가 지천을 만나는 곳에는 보행교를 둬 경로가 끊기지 않게 한다. 나무는 길 가장자리와 그늘숲에 모으고 잔디 중심의 시야를 비운다.

차량 주차·회차는 강변도로와 공원 경계에 둔다. 접속 지점과 회차 동선을 먼저 예약하고 장식을 배치한다. 도시는 지정 횡단 지점을 통해 공원과 이어진다. 단면 시안의 도로 아래 연결은 실제 높이 여유가 있는 기존 고가 아래에서 사용한다. 지상 도로 아래에 장식용 터널을 그리지 않는다. 지상 접속은 평면 횡단과 낮은 경사로로 해결한다.

수변 계단은 물을 바라보는 휴식 공간으로 만들고, 옆에 연속 경사로를 둔다. 실제 지면·수면 높이를 기준으로 설계하며 시안에서 강조한 고저차를 그대로 적용하지 않는다.

## 섬·파빌리온·보행

문화섬의 공연시설은 낮은 지붕과 열린 전면을 갖는다. 섬의 긴 방향에 잔디 객석과 산책 동선을 놓고, 양안 보행 연결의 끝은 실제 산책로에 접속한다. 기존 차량 교량·교각과 간섭하면 섬 출입 위치를 이동한다. 건축물과 나무를 늘려 섬 전체를 채우지 않는다.

세 파빌리온은 큰 정자·중간 정자·작은 정자로 구성한다. 크기와 지붕 높이를 다르게 하고 낮은 연결 데크를 남안 산책로에 연결한다. 부유 물리 없이 고정된 수상 구조물로 표현한다. 실내 콘텐츠·상점·공연 시스템은 만들지 않으며, 열린 외부 바닥과 데크를 탐색할 수 있게 한다.

보행 연결에는 다음 데이터가 필요하다.

- 안정적인 ID, 경로 점과 폭, 높이 표본, 끝점 연결 ID.
- 동일한 바닥 삼각형에서 파생하는 렌더 표면과 높이 조회.
- 난간·기둥의 위치 및 높이를 포함한 장애물, 건물 예약 영역.
- `pedestrian` 접근 속성. AI 차량망에 보행교를 넣지 않는다.

현재 `walkPhysics`는 지상 평면을 기준으로 점프·착지를 처리하고 물 판정을 직접 호출한다. 보행 경로 위에서는 발밑 표면 높이를 기준으로 걷기·점프·착지를 처리한다. 물 판정은 실제로 발을 지지하는 데크/교량 면적과 높이 안에서만 면제한다. 데크 밖 물까지 육지로 바꾸거나 차량에 같은 면제를 자동 적용하지 않는다. 보행교 입구는 차량 접근을 막고 도보 여유를 확보한다.

섬은 현재 물 판정의 타원과 렌더의 팔각형 사이에 차이가 있다. 접근 가능한 섬 외곽은 공통 footprint를 사용해 시각·물 판정·보행 판정이 일치하도록 한다. 수상 데크의 존재는 강 자체의 물 기하와 분리한다.

## 데이터와 책임

`createUrbanPlan()`이 최종 도시 계획의 소유자로 남는다. 원시 지형과 기존 간선을 입력받는 순수 생성 모듈로 새 배치 계산을 분리하고, 렌더러가 별도의 좌표를 만들지 않게 한다.

| 원본 또는 추가 모듈 | 책임 |
| --- | --- |
| `shared/urbanPlan.js` | 생성 순서, 최종 도로·블록·강변 계획 조합, 경로/교량 파생 |
| `shared/neighborhoodPlan.js` (추가) | 북안 선형, 남안 대각축, 접속점과 도로·필지 예약 계산 |
| `shared/riverfrontPlan.js` (추가) | 잔디공원·섬 시설·파빌리온·보행 경로·표면·예약 영역 생성 |
| `shared/river.js` | 강·지천·섬의 공통 기하와 물 판정 |
| `shared/worldLayout.js` | 새 도로와 공공부지 예약을 제작자·배경 필지 모두에 적용 |
| `src/world/models/riverfront.js` (추가) | 공통 계획으로 정적 시각 배치와 장애물을 생성 |
| `src/world/UrbanScenery.js` | 도로와 수변 시설 배치를 장면 데이터로 통합 |
| `src/world/walkPhysics.js` 및 도보 호출부 | 공통 보행 표면 조회와 지지 높이, 물 판정 연결 |
| `src/world/solidIndex.js` 소비 경로 | 시설물·난간의 공통 충돌 처리 |
| `src/world/Map.jsx` | 실제 도로와 구분되는 산책로·문화섬·파빌리온 표시 |

생성 순서는 지형/기존 간선 → 동네 선형 및 대각축 → 블록과 필지 후보 → 접속 정규화/차량 교량 → 수변 공공부지와 보행 연결 → 최종 예약/건물 배치 → 렌더·물리·지도·교통 소비다. 수변 생성기는 `urbanPlan`을 다시 호출하지 않는다. 차량 topology는 차량 도로만 포함하며 보행 연결은 별도 데이터로 관리한다.

기존 `plan.waterfront`는 북쪽 외곽 해안의 promenade/marina를 담고 있다. 강변 시설은 `plan.riverfront`에 별도로 담아 이 의미를 덮어쓰지 않는다. 시설 ID, 종류, 경계, 경로, 표면, 예약 영역은 이 객체에서 함께 나온다.

## 시각과 성능

기존 미니어처의 재질·계절 팔레트를 따른다. 잔디는 넓고 단순한 면, 나무는 작은 군집, 시설은 낮은 석재·목재·유리와 서로 다른 지붕으로 구분한다. 파빌리온 야간 표식은 기존 재질 발광을 사용한다.

정적 구조물은 기존 배치·공유 geometry/material 체계를 사용하고 그림자 caster 색인에 포함한다. low/medium/high에서 필수 바닥·난간·충돌·시설 위치는 같다. 장식 밀도만 조절한다. 표면과 점유 계산은 계획별로 캐시하고 도보 높이 조회에는 공간 색인을 사용한다. 매 프레임 전역 도로 또는 시설을 재생성하지 않는다.

## 생성 실패와 검증 기준

좁은 도시에서 시설이 안 맞으면 고정된 후보 순서로 옮기고 잔디·장식 면적부터 줄인다. 도로 폭이나 보행 통과 폭을 임의로 줄이지 않는다. 필수 목적지나 연결을 배치하지 못하면 진단에 실패 ID와 제약을 남기고 완료로 처리하지 않는다.

구현 완료 조건:

1. extent 1000/1600/1844/2164/3600에서 동일 입력의 계획이 결정적이며, 제작자가 전원 배치되고 도로·공공부지·수면과 건물이 겹치지 않는다.
2. 북안 곡선 생활도로와 남안 대각축이 기존 차량망에 실제로 연결된다. 새 도로 끝점에는 접속 또는 의도한 종단 사유가 있으며, 교량·고가 접속에 틈이나 높이 튐이 없다.
3. 공원 입구 → 잔디마당 → 문화섬 → 남안 산책로 → 세 파빌리온 데크를 도보로 이동할 수 있다. 보이는 바닥에서 침수 처리되거나 바닥을 관통하지 않는다.
4. 보행교와 수상 데크는 AI 차량 경로에 포함되지 않는다. 데크 밖 수면은 기존 물 판정을 유지한다.
5. 차도·회차 공간·보행 연결을 나무, 기둥, 난간, 충돌 상자가 막지 않는다. 품질에 따라 통과 가능한 공간이 바뀌지 않는다.
6. 지도와 항공 시점에서 북안 작은 곡선 블록, 남안 대각축, 넓은 공원, 낮은 문화섬, 세 파빌리온이 각각 읽힌다. 차량과 도보 시점의 전후 이미지를 남긴다.
7. 관련 도로·배치·물리 회귀 검사, lint, build, 브라우저 주행/도보 확인을 수행한다. 현재 작업 트리의 무관한 변경 때문에 발생한 실패는 분리해서 보고한다.
8. 생성 시간·필지 수·제작자 이동 수·정적 파트 수·draw call·프레임 시간을 동일 장면의 구현 전 기준과 비교한다. 시각과 성능을 실제로 확인한 범위를 완료 보고에 명시한다.
