# 강남형·강북형 대표 동네 2곳 설계

날짜: 2026-09-22
상태: 사용자 검토용 — 방향 승인 완료, 상세 설계 및 구현 계획 승인 전

## 목적과 단계

사용자는 서울의 강남·강북에서 연상되는 도로와 건물 밀도 차이, 탐험과 주행의 재미를 원한다. 실제 서울 지도 복제가 아니라 강을 건너면 길과 풍경의 성격이 달라지는 미니어처 도시가 목표다.

이번에는 대표 동네를 북안과 남안에 하나씩 만든다. 사용자가 실제 화면과 주행 결과를 확인하고 괜찮다고 판단한 뒤에만 강남·강북·강변 전체 재편으로 확대한다. 전체 확대는 이번 구현의 자동 후속 단계가 아니다.

별도로 승인된 육상 차량 제작자 카드 최대 폭 제한(280 CSS px와 화면 폭 25% 중 작은 값)은 후속 버그 수정으로 유지한다. 동네 생성과 별도 변경으로 검증·커밋하며 탐색·비행 모드는 보존한다.

## 현재 구조와 선택

- `shared/riverZones.js`에는 북안 저층·상가, 남안 아파트·상업 축 정책이 이미 있다. 강의 남북은 `riverBank`로 판별한다.
- `shared/urbanPlan.js`의 `districtBlocks`가 공통 밴드·베이 격자를 만들고 도로 및 `worldLayout`의 필지 배치가 이를 공유한다.
- 큰길·고속도로는 왕복 6차선이며 도색과 AI 차선·속도는 `shared/roadProfile.js`를 함께 읽는다.
- 단순히 골목만 덧그리면 기존 필지·건물·충돌과 겹친다. 도로와 필지를 함께 설계해야 한다.

접근 방식은 기존 격자의 장식만 변경, 두 곳의 블록·도로를 함께 변경, 전체 도시 생성 교체 중 두 번째를 선택한다. 첫 번째는 주행 차이가 작고 세 번째는 시범 단계의 범위를 넘는다.

## 두 동네의 체험

| 항목 | 강남형 시범 동네 | 강북형 시범 동네 |
| --- | --- | --- |
| 뼈대 | 기존 6차선 대로를 정면으로 삼은 정돈된 블록 | 간선 접근을 유지한 작은 블록과 짧은 연결길 |
| 내부 길 | 직선 이면도로, 대로 뒤 상업 골목, 두 방향 출입 | 엇갈린 T자 교차로, 연결 골목, 완만한 굽이 |
| 건물 배치 | 대로변 정렬과 일정한 보도, 뒤편 작은 상가 | 좁은 전면 여백과 연속된 저층 배경 건물, 작은 마당 |
| 대표 경로 | 대로 → 뒷길 → 다른 교차로로 복귀하는 순환 | 골목 → 작은 광장 가장자리 → 다른 큰길로 나가는 지름길 |
| 인상 | 길고 열린 시야, 정돈된 거리 | 코너마다 시야와 공간 폭이 바뀌는 촘촘한 거리 |

모든 길을 직선 또는 미로로 획일화하지 않는다. 강남에도 골목, 강북에도 접근 가능한 큰길을 남긴다. 새 도로는 기존 폭·속도 정책을 우선 사용한다. 언덕·새 터널·새 입체교차로·신호체계·경주 모드는 이번에 추가하지 않는다.

## 위치와 범위

기존 교량으로 왕래할 수 있는 북안·남안의 연결된 블록 묶음을 하나씩 선정한다. 지구 이름만으로 남북을 추정하지 않고 실제 강 위치를 사용한다. 기존 간선 접근, 필지 수용 여유, 자연·공공부지 회피를 기준으로 결정적으로 선정하며 ID로 동률을 해소한다. 같은 extent와 입력은 항상 같은 후보를 선택한다.

한 동네는 여러 코너를 돌아 순환할 수 있는 소규모 블록 묶음으로 제한한다. 정확한 경계는 구현 계획 전 후보 조사로 확정해 좌표·범위·연결도로 ID를 기록한다. 경계를 매 프레임 또는 제작자 정렬 순서에 따라 바꾸지 않는다. 작은 도시에서도 두 구역을 확보할 수 있는지 검증하고, 불가능하면 구역을 조용히 생략하거나 자연지대를 침범하지 말고 범위를 재검토한다.

시범 구역 밖의 간선·교량·강변도로·고속도로와 지형은 유지한다. 경계 도로를 이어야 하는 국소 접속부만 수정할 수 있다. 시범 구역과 무관한 지구까지 재설계하지 않는다.

## 공통 데이터와 생성 경계

동네의 프로필과 경계, 도로 연결, 필지 예약을 순수 shared 데이터로 관리한다. `urbanPlan`이 최종 도로망의 소유자로 남으며 렌더러나 지도에서 별도 도로를 생성하지 않는다.

생성 순서는 기존 간선·지형 제약 → 시범 구역 선택 → 구역 내부 도로와 필지의 공동 배치 → 경계 접속 정규화 → 기존 연결·clearance 검사 → 제작자 및 배경 건물 배치 → 렌더·지도·AI 소비다. `districtBlocks`/`worldLayout` 소비 계약을 호환시키고 중복 생성이나 순환 의존성을 만들지 않는다.

배치 데이터는 길에 접한 필지와 통행 공간을 함께 표현한다. 불규칙한 도로 밑에 기존 사각 필지를 그대로 남기지 않는다. 신규 곡선은 기존 중심선·노면 생성기를 재사용한다. 지도와 충돌·AI가 동일한 결과를 읽는다.

## 밀도와 보존 규칙

제작자 건물의 티어별 실루엣·높이 정책을 이번에 바꾸지 않는다. 특정 티어를 남북에 격리하지 않고 전원 배치와 ID 선택을 보존한다. 지역 분위기는 주로 블록 구성, 건물 전면 여백, 배경 건물 종류와 간격에서 만든다.

밀도를 높이려고 충돌 여유나 도로 폭을 줄이지 않는다. 배경 건물의 기존 인스턴싱·품질 예산을 유지하며 창문·간판마다 별도 DOM이나 실제 광원을 만들지 않는다. 새 모델군을 대량 추가하지 않는다.

필지 공급 변화로 기존 배치기의 제작자 주소가 달라질 가능성이 있다. 구역 밖 제작자 이동 수와 extent 변화를 측정해 보고한다. 시범 구역 수용량을 맞추기 위해 도시 전체를 크게 키우거나 대규모 재배치가 필요하면 구현을 멈추고 범위를 조정한다. 기존 좌표가 전부 고정된다고 약속하지 않는다.

## 연결과 주행 안전

두 동네 모두 기존 지상 도로망으로 연결되는 서로 다른 진출입 지점을 확보하고 최소 하나의 실제 주행 순환을 만든다. 강북형 대표 지름길은 양 끝이 도로에 연결돼야 한다. 의도한 막다른 골목은 별도 표식과 후진 탈출 공간을 갖추며 핵심 경로를 대신하지 않는다.

가로수·가드레일·주차 장식·건물·연석은 기존 도로 점유 검사에 포함한다. 장식으로 좁은 길을 막지 않는다. 승용차가 꺾어 들어갈 수 있는 회전 여유까지 검사한다. 대형 차량이 모든 골목을 통과할 수 있다고 가정하지 않는다.

AI는 기존 연결 경로·차선·도로별 속도 계약을 유지한다. 새 이면도로는 폭과 회전 검증 후 기존 경로 형식에 포함하고, 좁은 골목에 AI를 무조건 투입하지 않는다. 이번 단계에서 목적지 기반 길찾기나 골목 전체 AI 통행은 추가하지 않는다.

## 검증과 사용자 확인

1. extent 1000/1600/2164/3600 및 대표 제작자 분포에서 두 구역의 결정성, 필지 공급, 전원 배치와 비중첩을 검사한다.
2. 도로망 연결, 경계 포장 틈, 의도하지 않은 끝점, 시설물 침범, 교차로 회전과 교량 접근을 회귀 검사한다.
3. 같은 기준 면적에서 블록 크기, 교차점 밀도, 도로 길이, 건물 전면 간격을 비교한다. 강북형은 더 작은 블록·더 많은 경로 선택, 강남형은 더 긴 직선 시야가 실제 데이터와 화면 모두에서 드러나야 한다.
4. 같은 시간대·품질·카메라 높이의 전후 및 두 구역 비교 화면을 남긴다. 지도·항공 시점과 육상 차량 시점을 모두 확인한다.
5. 강남형 대로/뒷길 순환, 교량 횡단, 강북형 골목/광장 가장자리 순환을 직접 주행 검증한다. 제작자 카드 제한도 별도 근거리 검증으로 확인한다.
6. low/medium/high의 통행 공간을 동일하게 유지한다. 생성 시간·필지 수·파트 수·draw call·주행 프레임 시간을 같은 환경의 기준 빌드와 비교하고, 시범 두 구역 때문에 전역 비용이 급증하면 축소한다. 기준 수치는 구현 시작 전에 기록한다.
7. 관련 단위 테스트, 전체 world 회귀, scoped lint, 빌드와 브라우저 검증을 실행한다. 무관한 사용자 변경은 수정·커밋하지 않는다.

완료 보고는 두 동네를 찾을 위치, 비교 이미지, 주행 결과, 성능 변화 및 로컬 커밋을 포함한다. 푸시하지 않는다. 사용자가 체험의 차이를 확인한 뒤 전체 강남·강북·강변 확장 여부를 결정한다.

## 다음 승인 단계

이 문서 검토 후 후보 구역의 정확한 경계·정량 예산·파일별 작업과 검증 순서를 담은 구현 계획을 작성한다. 설계/검토는 Astra, 승인된 독립 구현은 Sol/high로 나누는 기존 선호를 유지한다. 구현 계획 검토 전 제품 코드는 변경하지 않는다.
